### 1.1   使用HTTP协议访问Web

根据Web浏览器地址栏中指定的URL，Web浏览器从Web服务器端获取文件资源（resource）等信息，从而显示出Web页面，像这种通过发送请求获取服务器资源的Web浏览器等，可称为客户端（client）

Web使用一种名为HTTP（Hyper Transfer Protocol，超文本传输协议）的协议作为规范，完成从客户端到服务器端的一系列运作流程

**Web是建立在HTTP协议上通信的**

### 1.3   网络基础 TCP/IP

通常使用的网络（包括互联网）是在TCP/IP协议族的基础上运作的，HTTP属于它内部的一个子集

#### 1.3.1   TCP/IP协议族

计算机与网络设备要相互通信，双方就必须要基于相同的方法

比如，如何探测到通信目标，由哪一边发起通信，使用哪种语言进行通信，怎样结束通信等规则都需要事先确定，不同硬件，操作系统之间的通信，所有的一切都需要一种规则，我们就把这种规则称为**协议**（protocol）

> TCP/IP协议族里包含的协议（先做大概了解）
>
> ICMP（Internet Control Message Protocol，互联网控制报文协议）是 TCP/IP 协议族中的网络层协议，主要用于传递网络错误信息和诊断网络连通性
>
> IEEE 802.3 是由 IEEE（电气与电子工程师协会）制定的以太网（Ethernet）标准系列，主要规定有线局域网中 MAC 层和物理层的相关技术规范
>
> FDDI（Fiber Distributed Data Interface，光纤分布式数据接口） 是一种基于光纤传输的局域网技术，主要用于早期对高带宽、高可靠性要求较高的网络
>
> IP（Internet Protocol，互联网协议） 是 TCP/IP 协议族的核心协议，工作在网络层，主要负责为数据包提供逻辑寻址和跨网络转发机制，使数据能够从源主机传输到目标主机
>
> TCP（Transmission Control Protocol，传输控制协议） 是 TCP/IP 协议族中的传输层协议，主要负责在两台主机之间提供可靠、有序、面向连接的字节流传输
>
> UDP（User Datagram Protocol，用户数据报协议） 是 TCP/IP 协议族中的传输层协议，主要用于提供简单、低开销的数据报传输服务
>
> PPPoE（Point-to-Point Protocol over Ethernet，以太网上的点对点协议） 是一种将 PPP（点对点协议）封装在以太网中的网络技术，常用于家庭宽带接入，让用户通过以太网建立宽带连接并进行身份认证
>
> DNS（Domain Name System，域名系统） 是一种用于将域名转换为 IP 地址的分布式命名系统，也是互联网基础设施的重要组成部分
>
> FTP（File Transfer Protocol，文件传输协议） 是一种用于在客户端和服务器之间传输文件的应用层协议，支持文件上传、下载以及目录和文件管理等操作
>
> SNMP（Simple Network Management Protocol，简单网络管理协议） 是一种用于监控和管理网络设备的应用层协议，常用于管理路由器、交换机、服务器、防火墙、打印机等设备
>
> HTTP（Hypertext Transfer Protocol，超文本传输协议） 是一种应用层协议，用于客户端与服务器之间交换网页、图片、视频、API 数据等资源，是 Web 通信的基础

协议中存在各式各样的内容，从电缆的规格到IP地址的选定方法，寻找异地用户的方法，双方建立通信的顺序，Web页面显示需要处理的步骤等等

像这样把与互联网相关联的协议集合起来总称为TCP/IP

#### 1.3.2   TCP/IP的分层管理

TCP/IP协议族里最重要的一点就是**分层**

TCP/IP协议族按层次分别为以下四层，**应用层，传输层，网络层，数据链路层**

> 其实TCP/IP协议族有4层和5层两种不同的说法
>
> gpt叙述的4层是应用层，传输层，网络层，网络接口层
>
> 5层则是应用层，传输层，网络层，数据链路层，物理层
>
> 只是划分方式不同而已，仅做科普

把TCP/IP层次化是有好处的，比如如果互联网只是由一个协议统筹，当某个地方需要变化时，就必须把所有部分替换掉，而分层设计过后，只需要把对应的层替换掉

各层之间接口部分规划好之后，每个层次内部的设计就可以自由改动

值得一提的是，层次化之后，设计变得相对简单了，处于应用层的应用可以只考虑分派给自己的任务，而不需要弄清楚对方在地球上的哪个位置，对方传输路线是怎么样的，能不能确保传输送达等问题

TCP/IP协议族各层的作用如下

- 应用层

决定向用户提供应用服务时通信的活动

> 它定义应用进程之间交换数据的协议规则，包括消息格式、请求与响应机制、数据含义以及应用层交互流程，使不同主机上的应用程序能够按照统一规则进行通信

TCP/IP协议族内预存了各类通用的应用服务，比如FTP和DNS，HTTP也处在此层

- 传输层

传输层对上层应用层，提供处于网络连接中两台计算机之间的数据传输

> 传输层是 TCP/IP 协议体系中负责为不同主机上的应用进程提供端到端数据传输服务的一层。它的核心任务是利用端口号识别通信进程，并根据所使用的协议提供不同的数据传输服务

在传输层有两个性质不同的协议：TCP和UDP

- 网络层

网络层用来处理在网络上流动的数据包，数据包是网络传输的最小数据单位，该层规定了通过怎样的传输路径到达对方计算机，并把数据包传给对方

与对方计算机之间通过多台计算机或网络设备进行传输时，网络层起的作用就是在众多选项内选择一条传输路线

- 数据链路层

用来处理连接网络的硬件部分，包括控制操作系统和硬件的设备驱动，NIC（Network Interface Card，网络适配器，即网卡），光纤等物理可见部分（还包括连接器等一切传输媒介）

硬件上的范畴都在链路层的作用范围内

#### 1.3.3   TCP/IP通信传输流

利用TCP/IP协议族进行网络通信时，会通过分层顺序与对方通信，发送端从应用层往下走，接收端向应用层往上走，用HTTP举例来说明

1. 作为发送端的客户端在应用层（HTTP协议）发送一个想看某Web页面的HTTP请求
2. 为了传输方便，在传输层（TCP协议）把从应用层处收到的数据（HTTP请求报文）进行分割，并在各个报文打上标记序号和端口号后转发到网络层
3. 在网络层（IP协议），增加作为通信目的地的MAC地址后转发给数据链路层
4. 接收端的服务器在数据链路层收到数据，按顺序向上发送一直到应用层

发送端在层与层之间传输数据时，每经过一层就必定会被打上该层所属的首部信息，反之，接收端在层与层的传输数据时，每经过一层就消除对应的首部

这种把数据信息包装起来的做法叫封装（encapsulate）

> 发送端的流程就像是
>
> HTTP报文 ——> TCP报文 ——> IP数据包 ——> 网络架构
>
> 最终在数据链路层形成一个
>
> 由以太网首部 + IP首部 + TCP首部包装起来的HTTP数据

### 1.4   与HTTP关系密切的协议：IP，TCP，DNS

#### 1.4.1   负责传输的IP协议

IP协议位于网络层，作用是把各种数据包传送给对方

确保传送到对方，则需满足各种条件，其中最重要的两个就是IP地址，MAC地址

IP地址指明了节点被分配到的地址，MAC地址指网卡所属的固定地址，IP地址可以和MAC地址进行配对，IP地址可变换，MAC地址基本上不会改变

> MAC 地址的全称是 Media Access Control Address，中文通常称为媒体访问控制地址，MAC 地址通常在网卡生产时就被分配好了，存储在网卡相关的硬件或固件中，用来标识网络接口。 但要注意，它并不是绝对不能改变的，**是可以被软件或系统配置修改的**

在网络里，通信的双方位于同一局域网的情况很少，一般都是经过多台计算机和网络设备中转才能连接到对方，在进行中转时，会利用下一站中转设备的MAC地址来搜索下一个中转目标，此时会用到**ARP协议**，是一种用来解析地址的协议，根据通信方的IP地址就可以反查出对应的MAC地址

**没有人可以全面掌握互联网中的传输情况**

#### 1.4.2   确保可靠性的TCP协议

TCP位于传输层，提供可靠的字节流服务

所谓的字节流服务（Byte Stream Service）是指，为了方便传输，将大块头数据分割成以报文段（segment）为单位的数据包进行管理，可靠的传输服务则是指，能把数据准确可靠地传给对方

一句话，TCP为了更容易传输大块头数据才将其分割，还能确认数据最终是否传到对方手上

为了准确无误地将数据送到目标处，TCP协议采用了三次握手（three-way handshaking）策略，握手过程中使用了TCP的标志（flag）—— SYN（synchronize）和ACK（acknowledgement）

1. 发送端首先发送一个带SYN标志的数据包给对方
2. 接收端收到后，回传一个带有SYN/ACK标志的数据包
3. 发送端再回传一个ACK标志的数据包，代表握手结束

如果整个过程中某个阶段发生中断，TCP协议会以相同的顺序再次发送相同的数据包

#### 1.4.2   负责域名解析的DNS服务

DNS服务是和HTTP协议一样位于应用层的协议，它提供域名到IP地址之间的解析服务

计算机既可以被赋予IP地址，也可以被赋予主机名和域名，比如www.hacker.jp

> 用户通常使用主机名或域名来访问对方的计算机，而不是直接通过IP地址，因为除非闲的蛋疼或者对方的IP地址简单得像1 + 1 = 2这种情况，没人想去记一串八竿子打不着的数字，说实话我电话号码都懒的记
>
> 但计算机不擅长处理一段有规律的英文组合，它更擅长直接处理一大串莫名其妙的数字，为解决此情况，DNS服务诞生了，可以通过DNS服务从域名找到对应的IP地址，或者反过来从IP地址找到对应的域名

#### 1.4.3   各种协议与HTTP协议的关系

举例说明IP协议，DNS服务，TCP协议在使用HTTP协议的通信过程中各自发挥了哪些作用

1. 我闲来无事想访问一下樱花动漫网页
2. 客户端向DNS发请求，告诉我樱花动漫首页的IP地址吧
3. DNS返回樱花动漫首页对应的IP地址
4. HTTP协议开始干活，它的职责是生成针对目标Web服务器的HTTP请求报文 ” 请给我樱花动漫首页的资源啊 “
5. TCP协议开始干活，它的职责是为了方便通信，把HTTP请求报文分割成报文段（按序号分割），把每个报文段可靠的传给对方（三次握手）
6. IP协议开始干活，它的职责是搜索对方的地址，一边中转一边传送（在数量不明的路由器等网络设备里中转）
7. TCP协议又开始干活了，这一次它负责把接收到的报文段按序号以原来的顺序重组为请求报文
8. 到达目标服务器，HTTP协议又开始干活了，对请求进行处理，原来你想要这台计算机上樱花动漫的资源啊

### 1.5   URI和URL

#### 1.5.1   统一资源标识符

URI是Uniform Resource Identifier的缩写

- Uniform

规定统一的格式可方便处理不同类型的资源，而不用根据上下文的环境来识别资源指定的访问方式，另外加入新增的协议方案也更容易

- Resource

资源的定义是 ” 可标识的任何东西 “

文档，图像，服务（例如当天的天气预报）全都可以作为资源

- Identifier

表示可标识的对象，也就是标识符

综上所述，URI就是由某个协议方案表示的资源的定位标识符，协议方案是指访问资源时所使用的协议类型名称

标准的URI协议方案有30种左右（http，ftp，file等），由隶属于国际互联网资源管理的非盈利组织ICANN的IANA管理发布

> ICANN（Internet Corporation for Assigned Names and Numbers，互联网名称与数字地址分配机构）
>
> IANA（Internet Assigned Numbers Authority，互联网号码分配局）

**URL是URI 的子集**

绝对URI格式

http://user:pass@www.example.jp:80/dir/index.htm?uid=1#ch1

- http:// —— 协议方案名


- user:pass —— 登录信息（认证）

> 指定用户名和密码作为从服务器端获得资源时必要的登录信息，此项为可选项

- @ —— 语法分隔符


- www.example.jp —— 服务器地址

> 地址还可以是IPv4和IPv6地址

- 80 —— 服务器端口号

> 指定服务器连接的网络端口号，此项也是可选项，若用户省略则自动使用默认端口号

- dir/index.htm —— 带层次的文件路径

> 指定服务器上的文件路径来定位特指的资源

- ？—— query 的起始分隔符


- uid=1 —— 查询字符串

> 针对已指定的文件路径内的资源，可以使用查询字符串注入任意参数，此项可选

- ch1 —— 片段标识符 

> 使用片段标识符通常可以标记出已获取资源中的子资源（文档中某个位置），该项也为可选项

> /dir/index.htm?uid=1#ch1
> │               │      │
> │               │      └─ # 开始 fragment，ch1 是片段名，不发给服务器
> │               └─ ? 开始 query，uid=1 是查询参数，会发给服务器
> └─ 第一个 / 表示路径从主机根开始，是绝对路径引用
